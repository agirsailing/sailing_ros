# Rosbag manager

`rosbag_manager_node` starts and stops a `ros2 bag record -a -s mcap` process.
It records discovered ROS topics; it does not read hardware ports or archive the
CSV files written directly by sensor nodes.

- Start service: `/local_cmd/start_recording` (`sail_msgs/srv/StartRecording`).
- Stop service: `/local_cmd/stop_recording` (`sail_msgs/srv/StopRecording`).
- State topic: `/local_state/recording_state` (`sail_msgs/msg/RecordingState`).
- Default output directory: `~/ros2_ws/rosbags/raw_recordings`.
- Runtime parameters: `config/params.yaml`.
- Endpoint names: `config/endpoints.yaml`; generated by the workspace build script.

The start and stop responses return the effective and last bag names. The state
monitor detects unexpected recorder exits. Starting the subprocess does not by itself
guarantee that DDS discovery and recording initialization have completed.

## Timing

Configure the two independent timers in `config/params.yaml`:

```yaml
process_check_rate_hz: 2.0
publish_rate_hz: 2.0
```

`process_check_rate_hz` polls the recorder process for unexpected exits.
`publish_rate_hz` periodically publishes the manager's current state on
`/local_state/recording_state`. Both must be finite and positive; zero is not
an event-only mode. Values are read at startup, so rebuild/install and restart
after changing the package YAML.

Start/stop handling and detected unexpected exits also publish immediately.
Routine process checks do not publish additional messages when nothing changes.
For example, `publish_rate_hz: 0.5` sends a periodic state every two seconds while
`process_check_rate_hz: 2.0` keeps checking the recorder every half second.
Timers share the node's executor: a blocking stop operation can postpone them
while it waits for the recorder to exit. Frequencies are nominal, not hard deadlines.

These settings do not throttle the recorded topics or alter their sampling rates.
There is no sensor `read_rate_hz` or input freshness check here: the manager handles
service requests and monitors a local process. Consumers must detect missing state
updates themselves; they are not changed by this timing refactor.

`launch/live_rosbag_manager.launch.py` starts the manager but does not automatically
start recording. The top-level orchestrator does not include this launch yet.
`config_rosbag_manager.py` is legacy reference code and is not used by the node.
